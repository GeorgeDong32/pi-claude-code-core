# Changelog

## Unreleased

### Breaking (type-only `./types` subpath — spec 2026-10-07 P1-1, D4=B)
- **`@georgedong32/pi-claude-code-core/types` no longer provides a runtime export.** The `readCoreStatus()` total reader (`types/core-status.mjs`) and the `CoreStatus` interface are withdrawn; the subpath keeps only the `CoreSnapshot` / `CoreCommand` / `CoreCommandResult` type declarations (`types/index.d.mts`). A runtime `import ... from ".../types"` now fails with `ERR_PACKAGE_PATH_NOT_EXPORTED`; type-only imports are unaffected. Consumers should duck-type the snapshot on `globalThis.__piClaudeCodeCore` (or subscribe via `snapshot.onChange`) — the bus, the legacy `__piPermissionModes` / `__pmWorkingStats` aliases and cctui's own fallback reads are unchanged. No runtime consumer was found in the searched workspace; ship as a minor-version breaking bump (0.3.0 → ≥0.4.0).

### Changed (goal turn lock narrowed to real stops — spec 2026-10-07 P0-2, D3=A)
- **A goal no longer locks the turn on non-progress tool calls.** Previously, with an active auto-continue goal, any tool outside the progress list (`obs_recall`, `subagent`, MCP tools, `codemode` and its nested calls, …) set the same in-turn stop lock as a real stop, so e.g. a parallel `[obs_recall, edit]` reply had the `edit` rejected with a bogus "goal was already stopped" reason and codemode was unusable during goals. Now only the four real stop tools lock the turn after a successful execute (`pause_goal` / `abort_goal` / `update_goal=complete` / `apply_goal_tweak`); failures and audit rejections never lock, and the lock still resets on the next `turn_start`. The continuation rhythm is unchanged (it was always driven by `agent_end`). Same batch: the progress-exception check now reads the host's real `event.input` field — the old `event.args` read meant the "bash echo" and "read under `.pi/goals/`" exceptions never fired (they were counted as progress and reset the get_goal reminder).

### Changed (small refactors & cleanup — spec 2026-10-07 P3-1)
- **`plan_ready` approval now updates the plan-todos widget when execution starts** — the three plan→auto transitions (menu `/plan-execute`, the approval dialog, the agent_end offer) run through one `startPlanExecution`; the plan_ready path previously missed the widget sync after the mode flip.
- **web-gov / mcp-gov config reads are cached and warn on corruption**: `pi-core-web.json` and `mcp.json` go through the shared settings-JSON reader (malformed input warns once and falls back to the builtin list / empty inventory instead of silently falling back), with stat-fingerprint caches so unchanged files are not re-read per adjudication. Limit: in-place edits preserving mtime and length stay invisible until the next stat-visible change.
- **review internals**: one command-execution adapter replaces three copies (spawn error messages are now preserved everywhere); the unreachable `diff-file` target kind is deleted (`--diff` was already a silently-skipped flag; old manifests keep reading); `resolveReviewTarget` no longer samples `git status` early — the one sample in `acquireLocalDiff` decides the dirty verdict, so edits made during workspace preparation are no longer missed. The get_goal nudge says "recently" instead of the wrong "this turn". **Headless family first-seen now suggests its allow rule**: with no UI (headless runs, subagent children) an unauthorized family first-seen call still fails closed, but the block reason appends the family's own suggested rule and a retry hint (e.g. "add the rule `mcp_exa_*` to your permission rules in a parent/interactive session, then retry") — no grant is written and family first-seen never enters the parent-forwarding protocol.

### Changed (memory writer engine + queue-drain relocation — spec 2026-10-07 P2-3)
- **Memory document writes are centralized and atomic.** A new `memory/writer.ts` owns write/remove/reindex — the only paths that mutate memory documents or MEMORY.md. Imports that previously used plain `writeFileSync` (hermes/claude importers) now land through the unique-tmp+rename primitive with the scan cache invalidated on success and the tmp cleaned on failure; the two frontmatter serializers (store's renderFile + the importers' inline template) collapsed into one. The index reconciler moved to the writer: a failed index write keeps the old MEMORY.md and is never cached as a success. Project identity now has two named derivations in `paths.ts` — `fullProjectKey` (routing/matching authority) and `friendlyProjectHint` (display tail) — replacing three scattered inline copies with unchanged semantics. Observable reliability change: import-time crashes can no longer leave half-written memory files.
- **The queue drain orchestration moved out of automation.ts** into `memory/queue-drain.ts` (ports: complete / applyOps / blacklist), directly testable without the hook harness; automation keeps settings, correction/review scheduling, prompt templates and hooks, and aggregates the returned diagnostics. ConversationPart now lives with the queue (its type owner).

### Added (structured usage channel — spec 2026-10-07 P2-4, XPKG-08)
- **`modes.usage`**: raw usage numbers on the snapshot — `input/output/cacheRead/cacheWrite/cost` plus optional `tps`, `ctxTokens`, `ctxPercent`, `contextWindow` — derived from the SAME working-stats snapshot call as the `workingStats` string (no extra host reads; the AR1005-ST cache and invalidation table are untouched). Only finite non-negative numbers are published; a missing required cumulative field omits the whole object; unknown optionals are absent, never faked as 0 (real zeros are preserved). Session switch/shutdown explicitly clears it; mode-only patches keep the latest value. The string format and the legacy `__pmWorkingStats` key are unchanged; consumers fall back per-field to their own tracker when a field is absent.

### Added (bus cross-package surface — spec 2026-10-07 P1-1, XPKG-01..07/09)
- **`snapshot.instance`** — every snapshot now carries a random per-bus-instance id. pi builds a NEW bus on `/reload` while globalThis still serves the old snapshot; consumers detect the swap by comparing `instance` (old cores without the field: compare onChange identity) and re-subscribe. Patches can never overwrite the field.
- **`display.footer` is now actually rendered and multi-source safe.** Economy-module degrade lines previously published at factory-load time (a bus-discipline violation), overwrote each other (shallow-merge last-writer-wins), and nobody rendered them. A new `ui/footer-lines.ts` helper merges lines per source into one whole-array publish (per-bus-instance maps — no cross-reload leakage); the degrade warning still prints at load time, and the footer line is published from the first `session_start`. The core modes footer appends the channel's lines (dim, width-clamped) after its own two lines while it holds the slot; a live cctui's cc-footer renders them instead (joint acceptance with the TUI spec). After an explicit `/claude-tui off` the host stock footer shows nothing from this channel by design.
- **`goal.widget.goal.costUsed?`** added to the published types (the producer already shipped it).
- Contract rows XPKG-01..09-HOST registered (notification tail-queue negotiation, onChange, instance, obs_recall details protocol, then_run param shape incl. the `{command}` object, the cctui callArgsFor field list, display.footer ownership, modes.usage placeholder for P2-4, and the aboveEditor widget-ordering host assumption as a todo). The cctui tool-registration row was revised: cctui registers no tools since 1.8.0.

### Fixed (goal drafting send-failure reset — spec 2026-10-07 P0-2 CORE-05)
- **A failed goal-draft start no longer leaves the drafting gate stuck.** When `sendMessage` threw while starting `/goal`/`/sisyphus` intent discussion, `confirmationIntent` stayed set: the tool set remained in drafting form and accounting/turn/agent handlers kept early-returning for a draft that never started. The catch now resets the intent and re-syncs the tools (same shape as the tweak path). The turn-lock strategy and the G3 `event.args→event.input` fix from the same spec remain deferred pending the D3 decision.

### Fixed (memory-queue cross-worker claim — spec 2026-10-07 P0-3)
- **Two automation instances / pi processes can no longer drain the same queued record concurrently.** The drain previously read the queue and called the model with no ownership: overlapping sessions double-counted attempts and double-applied ops. The queue now runs a single-rename ownership protocol: claiming a record renames it to a unique `<ready>.claim.<pid>.<ts>.<nonce>` file (re-read from disk after claiming), failures rename it to a unique retryable `<ready>.pending.<nonce>`, and stale claims are recovered only past a 10-minute TTL plus a dead-owner probe. GC counts claims toward the 2MiB soft budget but never deletes a live worker's file; same-session replacement and budget eviction also claim-verify-settle instead of unlinking enumerated paths. This is a retrying best-effort queue, not exactly-once: a crash between apply and settle can re-apply (window disclosed in the docs). Staged-record files and the v1 record format are unchanged.

### Fixed (plan-mode permission precedence — spec 2026-10-07 P0-1)
- **Plan mode now enforces its read-only hard limits ahead of allow/ask permission rules.** Previously an `allow` rule (`Edit(src/**)`, `Bash(npm run build:*)`) short-circuited the gate before plan's checks ran, so plan mode happily executed writes and mutating commands; and a read tool hitting an `ask` rule prompted but the user's **Block was silently ignored** (the call passed anyway, plus a bogus compliance reminder next turn). The order is now: rule deny → plan hard limits (never prompt) → ask verdict (prompt/forward, result honored) → allow verdict → plan allowlist. Users who relied on allow rules to "open a side door" in plan should switch to auto/ask mode for the execution phase.
- **Family-governed MCP tools stay usable in plan** when their family adjudicates allow (allow rule, session grant, or first-seen approval) — unchanged behavior, now pinned by tests; their remote schema params (`command/run/cmd/then_run`) are no longer misread as local shell by plan's embedded-command scan (review R2: the old early generic scan could block an already-authorized MCP call). MCP-shaped calls with NO family remain denied (fail-closed).
- **The embedded-command gate now recognizes the real `then_run: { command }` object** that action-fusion registers (it previously only scanned string / string[] forms, so the object form silently bypassed the gate in every mode). `auto`/`ask` modes now also check this form; `bypass` is unchanged; outside plan an explicit allow rule still takes precedence.



### Added (sites entries carry toolCallId — OBS-09-SITES row correlation)
- **`observation.sites[].toolCallId`**: each per-site savings entry now carries the source tool result's `toolCallId` (optional, additive). The context projection rewrites only the provider request — the session transcript and the tool rows the user sees keep the original shape — so content shape cannot locate which row was packed; `toolCallId` is the only reliable display-side key to correlate a flashed saving with its tool row. Malformed sources degrade to field omission, never a throw; old-shape entries (without the field) and readers remain unaffected.

### Added (per-site observation savings on the bus — OBS-09-SITES)
- **`observation.sites`: display-only single-shot savings for the TUI.** The capability-bus `observation` channel gained an optional `sites: ReadonlyArray<{ tool, id, avoidedTokens }>` field: on each request where an observation is FIRST replaced (the `previousSends === FULL_SENDS` transition — the same single-shot semantics upstream SoL-Pi flashes in `showSolPiSavings`), the published patch carries one entry per first-replaced observation with that observation's `removedTokens`. The field is additive and optional: old publishers leave it undefined and old readers are unaffected (the then-current `readCoreStatus` whitelist never included observation; that reader was later withdrawn — see the Breaking entry above). It is display-layer data only — never part of a provider request or the projected messages (module invariant 9); packaging behavior, the ledger audit and `obs_recall` are unchanged. Pinned end-to-end through the real extension + real bus (exactly one sites-carrying publish per first-replacement request, none after) and as a bus-shape/backward-compat contract.

### Fixed (cross-repo review reads the TARGET repo's rules — spec 2026-10-05 AR1005-RV)
- **`/review` now discovers rule files in the final target workspace, not the calling repo**: `prepareRun` ran `discoverRulePathsLocal(callerCwd)` BEFORE the workspace even existed, so reviewing a repo that HAS rules (AGENTS.md, `.pi/rules/…`) from a caller that has none produced `rulePaths: []` and silently skipped the rulesheriff lane (the spec's reproduced case). Discovery now runs after the workspace retries/HEAD-mismatch checks settle, against the FINAL `workspacePath` — the reviewed code owns which rules apply. The caller keeps owning config loading, run artifacts and manifest/diff/workflow writes; `manifest.rulePaths`, `ChangeProfile.rulePaths`, rulesheriff routing and the directive consume the one prepared value (relative paths resolve against the workspace; the frozen manifest field shape is unchanged). gh-pr-diff authority, force-push retry semantics, local/diff-file workspace selection, rulesheriff config priorities and artifact paths are untouched. Pinned through the REAL `prepareRun` with a controlled clone that plants the target's rule files (six cases incl. the retry-replaces-first-workspace race and lite routing).

### Changed (stable observation placeholder memo — spec 2026-10-05 AR1005-OB)
- **Hot requests no longer re-scan large tool results for their placeholder excerpt**: `ProjectionState` now owns a stable placeholder memo (keyed by the existing root/toolName/toolCallId identity; value = the placeholder string + token estimate only — no full-text copies). The head/tail complete-line construction — a full-text scan measured at ~26 ms per request for an 8 MiB result — ran on EVERY replacement request; it now runs exactly once per identity per process (measured: 1 construction across 51 requests at 16 KiB / 2 MiB / 8 MiB, and 5 for five 2 MiB results; hot requests cost ~0.001 ms). Zero constructions happen during the full-send phase; a failed ledger append keeps the computed memo while the send counts/savings stay uncommitted (per-request retry, per-message fail-open preserved); the memo never crosses roots/tools and regenerates after a restart. Ledger audit rows are still appended per replacement request — the memo never skips the audit; disk id/hash/filePath, FULL_SENDS, sentinel streak and first-savings semantics are unchanged.

### Changed (streaming working-stats read cache — spec 2026-10-05 AR1005-ST)
- **`message_update` streams no longer re-read the session branch per chunk**: a new `modes/working-stats.ts` cache owns the stats snapshot and the context-usage snapshot behind a cheap key (sessionManager instance + sessionId + leafId — the legal empty-branch null is cacheable; a missing/throwing getter falls back to the uncached path on old hosts). Measured through the real modes hooks: after warmup, 200 message_updates at a 10 000-entry branch cost **zero** `getBranch` and **zero** `getContextUsage` calls (baseline made 200 `getBranch` calls — the reproduced ~2 M parent-map reads), and the benchmark holds at 1 K/10 K/50 K branches with only O(1) cheap-key reads per event. Invalidation follows the lifecycle table: reset on session_start/session_tree/session_shutdown, invalidate on session_compact, mark-dirty on message_end (fires before the host append; the leafId key also moves), usage invalidation on model_select, one forced committed read on turn_start/turn_end (turn_end previously read the branch TWICE), usage-only refresh on before_provider_request (no unconditional branch re-sum). Failed reads are never cached as successful empty snapshots — the next event retries. Display text, TPS formula, publish rhythm and legacy keys are unchanged; contract AR1005-ST-HOST pins the real-SessionManager leaf-identity signal (⑩) and registers the message_end-before-append run-loop ordering as a Phase 4 todo (⑪ — the cache never relies on it alone).

### Fixed (mid-stream ctx% regression in the working-stats cache — AR1005-ST, adversarial R1)
- **The `% ctx` line no longer disappears mid-stream on real hosts**: the turn-boundary forced refreshes called the new stats cache with a host shape missing `getContextUsage`, and the cache treated "capability absent" as "usage fresh" — so the first forced read cached `usage: undefined`, and every subsequent `message_update` key-hit reused it, hiding the context-usage line for the rest of the stream (test fakes without the capability masked this). All snapshot call sites now share one capability-consistent host shape, and a capability-less read can never mark usage fresh (one `typeof` check, zero host reads) — a later capability-bearing read always recovers. Pinned by a regression test.

### Changed (rules activations share a per-turn budget — spec 2026-10-05 AR1005-RU)
- **Rule activations within one turn now cumulatively share `DYNAMIC_STEER_MAX` (8 000 chars)**: a turn spans `turn_start` → the next `turn_start`, and every tool call in between draws from the same budget epoch. Previously each activation message was checked against the budget ALONE — one read hitting three 6 K rules sent ~18 K characters in a single turn (reproduced; baseline red: `expected 18036 ≤ 8000`). Delivery ladder per first-hit rule: full text when it fits the REMAINING budget → the existing "Read on demand" pointer → a short pointer (complete readable path, minimal note — paths and bodies are never truncated) → nothing this turn, with the rule left unactivated and retried on the next matching tool call (no background queue, no new delivery时机). A successfully sent pointer still counts as session-activated (the historical oversized-single semantics). Sends that throw synchronously roll back their reservation and stay eligible; the reserve-send-rollback runs in one synchronous pass, so parallel tool calls and re-entrant adapters cannot double-spend. Unbudgeted single-rule output is byte-identical; only over-budget turns degrade (full → pointer → next-turn retry).

### Fixed (goal timing fragments — spec 2026-10-05 AR1005-GO-A)
- **Sub-second goal activity is no longer silently discarded**: `accountProgress` floored each event's elapsed time to whole seconds and then reset the clock — every settle lost the remainder, so 8 × 250 ms tool-end events recorded 0 s of a real 2 s, and the next second recorded only 1. A new `goal-accounting.ts` clock module owns the segment start plus each unfinished goal's millisecond carry: settle returns floor((elapsed + carry)/1000) and keeps the remainder (zero-token/zero-cost events keep their fragments too); preview is a side-effect-free display read; pause (drafting / user pause / focus switch) drops the segment but keeps per-goal carries; completion/clearing releases a goal's carry. Carries never cross between goals. Disk records stay integer `activeSeconds` (frozen format, no new fields) — a process restart loses at most the current segment's sub-second remainder, never per-event loss again. Wall-clock timestamps (`updatedAt`, ledger `at`) are unchanged; the clock reads a monotonic time source (injectable in tests).
- **One accounting event parses the focused goal file exactly once (GO-B)**: `accountProgress` now threads a per-event read context from the pool reconcile into the persist prompt-merge — the focused file was previously read+parsed twice per event (reconcile pool read, then `mergeGoalPromptFromDisk` inside persist). Measured: N parses per event at N goals (baseline N+1), zero extra focused reads. The context is per-synchronous-segment only: it never crosses events or survives an await, so external objective/status/autoContinue edits and deletions are observed by the very next event (pinned), and the zero-usage early return stays after the reconcile so external cancel/delete detection never skips. The full-pool reconcile and the preserveMemoryUsage max-merge are unchanged; `writeActiveGoalFile`'s path/symlink safety and atomic write are untouched.

### Fixed (then_run success badge + zero-wrap discipline — spec 2026-10-05 AR1005-FU)
- **Successful fused runs now actually show the success badge**: the result-status scan looked for a `[then_run:ok]` token that production never writes (it writes `[then_run:succeeded]`), so every successful `then_run` rendered badge-less. Result interpretation moved to one pure module (`action-fusion/outcome.ts`): the structured `details.thenRun` outcome is the first authority — a command log containing the opposite marker can no longer flip a known success — and text compatibility (legacy replays without metadata, thrown failed/skipped error results) is line-anchored (a protocol line or a production text-block start; the legacy `ok` alias stays recognized for history; prose merely containing the token no longer matches). UI label text unchanged (`✓ ok`); the protocol token is NOT renamed.
- **Plain write/edit can no longer be badge-wrapped by their own output**: renderers now consume the host render facts (`ToolRenderContext.args`/`isPartial` — contract AR1005-FU-HOST, compile-pinned): a call whose args carry no `then_run` returns the builtin renderer object untouched even when the result body contains a marker, and partial/streaming results never show a terminal state. Hosts without those fields keep the legacy marker-scan path. `fusedCount` keeps counting only real structured successes; interpretation never rewrites `content`/`details`.

### Fixed (goal audit pre-abort + session release — spec 2026-10-05 AR1005-AU)
- **A pre-aborted `update_goal` no longer starts audit model work**: the completion-audit envelope now establishes its internal-cancellation result first, then connects the tool signal, then checks its current state — a call that is already aborted when the audit starts never invokes the auditor and returns the existing rejected outcome ("aborted by user, goal remains active"), while the started event and the `completion_requested`/`audit_started`/error `audit_result` ledger semantics stay as they were ("started" = the flow was requested, not that the model ran). Timer and both abort listeners are released on every exit path.
- **The auditor session cannot leak on any path**: the moment session creation resolves, the session is covered by a try/finally over its entire remaining lifecycle — cancellation during creation skips the prompt and disposes exactly once; `subscribe`/`prompt`/`unsubscribe` failures (including a throwing unsubscribe) all still dispose, each cleanup step guarded so one failure cannot skip the other; a creation rejection never calls a nonexistent disposer. A late completion after the flow already timed out or aborted can only clean up — it returns an aborted error outcome, never an approval. `sessionAdapter` is the new internal test seam (controlled adapter vs the real `createAgentSession`).

### Fixed (recall request lifecycle — spec 2026-10-05 AR1005-RC)
- **A session being replaced/shut down can no longer crash or ghost-deliver recall**: the recall machine gains a terminal `dispose()`; `session_shutdown` (any reason) disposes it synchronously, `session_start` defensively disposes for reload/resume drivers, and rebuilding/closing recall (model or settings change) disposes the old machine before the new one exists. Every request now owns a generation + AbortController + wait timer + cancelled resolver, so a newer message, abort, dispose or replacement invalidates it immediately — an in-flight `await` returns null right away (never hangs on a selector that ignores the signal) and a LATE completion reads no history, delivers nothing, mutates nothing. The baseline defect — reproduced against the real `ExtensionRunner`: after `invalidate()` a parked selection's completion read the stale ctx inside a void'd promise chain → `unhandledRejection` — is now pinned by contract AR1005-RC-HOST (isolated subprocess; zero sends, zero unhandled).
- **`onUserMessage` is now a total promise**: entry-stage throws (files/history/derive) and deferred-stage throws (history re-read/assemble/deliver) converge to null with at most one controlled diagnostic per failed request — the steer wiring's `void machine.onUserMessage(...)` can no longer produce an unhandled rejection. Deferred delivery commits its run-dedup and delivery counters only AFTER `deliver()` returns successfully (a throwing `sendMessage` on a stale session no longer permanently marks the file as delivered). Normal agent_end still lets an in-flight selection complete and deliver (v1.2 semantics preserved); the wait timer is cleared on every exit path.

### Fixed (JSON extraction string fidelity + lazy candidates — spec 2026-10-05 AR1005-JS)
- **`lib/json-lift.ts` repair no longer rewrites string bodies**: when a model reply had BOTH a genuine trailing comma and a string containing `,}` / `,]`, the old string-blind regex repaired the real comma AND rewrote the string (`"literal ,} sequence"` silently became `"literal } sequence"` — reproduced against the real parser). Repair is now a character-state scan tracking strings and backslash escapes: only an OUTSIDE-string comma followed by whitespace and `}`/`]` is removed, together with that whitespace; everything else passes byte-identical. Affects all four consumers (modes classifier verdicts, memory ops, recall selection, review verdicts).
- **Valid fenced/whole-text JSON no longer pays the span scan**: candidates now come from a private lazy generator shared by `jsonCandidates` (collects) and `liftJson` (iterates); the first accepted candidate ends generation, so the string-aware balanced-span scan — quadratic on pathological inputs (2K/8K/32K `{` measured 5.3/55.9/887.8 ms at baseline) — never runs for inputs whose fence or whole text already parsed. Candidate order and dedup semantics are unchanged. Inputs that still NEED the span fallback keep the disclosed quadratic worst case (deliberate, per spec AR1005-JS-03).

### Fixed (goal audit bounded-wait — spec 2026-10-04-goal-audit-hang-fix)
- **`update_goal` audits can no longer hang forever**: the completion audit now runs under a total budget (default 10 min, `auditTimeoutMs` in `.pi/goal-auditor.json`, floor 60 s). Root cause fixed live on 2026-10-04: the in-process auditor's own `find /Users/gd32 …` wedged in `~/Library/CloudStorage` (File Provider getattrlistbulk), the bash tool has no timeout, and `session.prompt()` took no signal — so the tool result never came back and the whole session froze, un-Esc-able. On expiry (or user abort) the audit now returns a rejected outcome with a `timed out`/`aborted` message, the goal stays active, and the audit is re-runnable; timeout aborts the auditor session via `AgentSession.abort()` (verified against the 1.0.1 run-loop: `prompt()` settles after abort) and the in-memory session is disposed. The auditor prompt and system prompt now forbid home/CloudStorage/network-volume scans and long-running foreground processes, confining inspection to the project directory. Unit regression (hung fake auditor → timed-out rejected outcome, abort propagation) pins the guarantee; bash-tool timeout injection was investigated and dropped (no option point in `BashToolOptions`; total budget covers it).

### Added (goal cost accounting — spec 2026-10-04-goal-cost-accounting)
- **Goal usage now carries USD cost alongside tokens**: `GoalUsage.costUsed` (fractional, upgrade-safe — pre-cost records read as 0) accumulates `usage.cost.total` from parent assistant turns AND from `tool_result` events that report execution usage (subagent runs, codemode `models.classify`/`generateImages`). Fixes the structural undercount verified 2026-10-03: three reviewer subagents (1.94M tokens / $0.49) were invisible to the goal ledger because only `role==assistant` messages were counted. Cost renders in the goal footer, one-line summary, `/goal` panel, compaction summary, pool list, "goal achieved" line, and archive report (2 decimals ≥$1, 3 below — flash-tier rounds read $0.023, not $0.02).

### Changed (pi 1.0.x adaptation — spec 2026-10-03-pi-1.0-adaptation)
- **Host compatibility widened to pi 1.x**: all four `@earendil-works/*` devDependencies move 0.99.1 → 1.0.1, and the three earendil peerDependencies open their ceiling from `<1.0.0` to `<2.0.0` (floors unchanged). Plan-mode denial semantics unchanged (META-04).

## 0.2.1 (2026-10-03)

### Changed (architecture review 2026-10-03 — C2/C3/C4)
- **`/compact` no longer waits on a memory-flush LLM call (~10s typical, 60s cap)**: the awaited `session_before_compact` flush had relocated the old shutdown stall to every compaction. Compact now stages the unextracted tail as a queue record through the same zero-LLM seam as shutdown (one shared `stageUnextractedTail` — the two paths can no longer drift); the next same-project `session_start` drains it in the background.
- **`modes/utils.ts` (1247-line nine-concept grab-bag) split into concept modules**: `bash-analysis.ts` (tiered bash adjudication), `path-safety.ts` (outside-cwd/sensitive paths + project identity), `outside-writes.ts` (snapshot engine), `plan.ts` (plan.md file + plan text grammar), `mode-prompt.ts` (anchored injection + skills filter), `auto-risk.ts`, `ui/format.ts`. Pure move — disk paths, behavior, and the contract-pinned `getPlanFilePath` layout unchanged.
- **JSON-lift unified in `lib/json-lift.ts`**: one string-aware implementation replaces four drifted copies (modes classifier, memory ops, recall selector, review verdict). Fixes a real recall-selector bug — a `}` inside a string value broke span extraction and silently counted a parse failure. Trailing-comma/BOM repair now applies to all four consumers; review's brace-lift fallback now also fires when fenced blocks parse but are not verdict-shaped.
- **observation-pack: large tool results are analyzed and stored once per process, not once per provider request** (arch review C1): the projection state now memoizes candidate identity (keyed root/toolName/toolCallId — tool results are immutable in the append-only transcript) and skips the EEXIST full-read + re-hash verification for already-stored objects. Steady-state requests cost one Map.get + a placeholder slice instead of ~3× sha256 + a full disk read per >10KB result; fail-open retry semantics unchanged (a failed store is not memoized).
- **Memory auto-extraction now runs at run end, not mid-run**: the background review (bulk memory extraction) used to fire the moment a turn threshold hit — extracting from a conversation still in flight, and repeatedly on long tool-heavy runs. It now fires once per completed run (`agent_end`), with a bounded 60-part window (a monster run extracts its most recent window; the prefix waits for the next pass) and an empty-window guard (no LLM call when nothing new accumulated). User corrections still capture within 3 turns (their freshness window is what matters).
- **`/memory` no longer mislabels recall as "unresolvable" on a fresh session**: the panel read the last agent-turn's state, so before any turn a configured-and-valid `memory.recallModel` was reported as `recallModel unresolvable`. The panel now re-attempts machine creation before reporting (idempotent, no LLM call); genuinely unresolvable refs still report as such.
- **The memory policy now names the REAL project-memory directory**: the injected `<memory-policy>` block said `PROJECT memory (<project>/memory/)` — a literal directory inside the repo — while the implementation reads/writes `~/.pi/agent/projects/<git-root>/memory/`. A session following the literal text wrote memories into the repo root (untracked, never indexed, never recalled). The policy now interpolates the actual absolute path and explicitly forbids the in-repo `memory/` location (regression-pinned at both the unit and e2e seams).
- **memory: per-message duplicate work eliminated on three paths** (arch review C7): recall reuses the entry-time candidate pool at deferred delivery (the second `files()` directory scan per selection is gone; the two `deriveHistory` passes stay — they are semantically required, RV-07); `conversationParts` walks the branch backward and stops at the window (was: full-branch text extraction to keep the last 6/60 entries); `scanMemoryDirCached` gains a 1s fresh-window (second and later scans in a turn skip the readdir+stat fingerprint pass) with explicit invalidation wired into every internal write path (`atomicWriteFile`/deletes/consolidate/importers). External edits outside pi are now visible within ~1s instead of instantly.
- **goal: paused-goal auditor objection now carries the goalId header** (arch review C6): the two hand-copied `[AUDITOR REJECTION]` prompt injections (an upstream copy-paste drift — same copy, drifted headers, one unreachable extra gate) are unified into one `auditorRejectionBlock` builder; the paused prompt's block now matches the `[AUDITOR REJECTION goalId=…]` marker format used everywhere else in the goal prompt family. The render trio moved to `goal/renderers.ts` (no behavior change).
- **alt+t now belongs to the effort module and can no longer corrupt the effort state on single-level models** (arch review C5): the old hardcoded six-step table lived in modes and probed by WRITING each candidate level (`setExplicit`) until one stuck — on a model supporting only one level it pinned a clamped value into the persistent explicit slot, flipping the source to "session" and suppressing per-mode profile effort for the whole session. alt+t (and ctrl+shift+e, which had the same flaw) now share one model-aware cycle with a zero-write guard: single-level models get a notice instead of a corrupting write, and the cycle follows the model's actual supported levels. The stateful model-profile half of modes moved to `profile-apply.ts` (pure internal move).
- **session_recall works on real machines again, and is now bounded** (arch review C8): the sessions-dir path used the projects-layer naming (`-Users-…`) while pi writes the sessions layer with wrapping dashes (`--Users-…-`) — the tool silently returned "no sessions found" for every real project (found by adversarial plan review R2 against the live machine). Now fixed; additionally the scan is async (no more event-loop blocking on large session dirs), bounded by three caps (200 files / 1MB per file as a PARTIAL read, never a whole-file skip / 8MB total budget), and appends a transparency footer (`scanned=… truncated_size=… budget=… bytes=…/…`).

### Fixed (memory automation survived in-process session switches — spec 2026-10-03 A1)
- **A dead AbortController no longer silently kills all memory automation after `/new` `/resume` `/fork`**: the host fires `session_shutdown` (whose cleanup aborts the shared controller) and then REUSES the same handler closures for the next session in the same process — the review gate `!signal.aborted` stayed false forever, the cursor froze, counters never reset. `setupAutomation` now resets every per-session closure state and re-arms the controller on `session_start`. Pre-existing bug found by adversarial review; the queue design depends on the fix.

### Changed (memory exit path zero-LLM — spec 2026-10-03-memory-exit-flush)
- **`session_shutdown` no longer runs an LLM flush**: the host awaits every shutdown handler serially with no timeout, and the old awaited 10s flush on the session model measurably stalled EVERY long-session exit for the full budget (CPA→glm-5.3 on a real 23KB tail window: 11–12.4s cold, 10.5s even with a cache hit — generation speed, not prefill, was the bottleneck). The handler now stages the unextracted tail (cursor-relative suffix, ≤60 parts × 2000 chars) as ONE atomic JSON record under `~/.pi/agent/memory-queue/`; the NEXT same-project `session_start` drains it in the background (≤5 records per drain, ≤3 attempts per record with pre-call attempt persistence, exact `projectsDir` routing, 7-day age cap, 2MB dir GC, apply-fatal = consume). Records are a plaintext second copy of the session tail — disclosed in `/memory` docs. Contract-registered under P0-CT-09.
- **Side-channel model fallback chain is now `memory.model → memory.recallModel → session model`** (was `memory.model → session model`): a user who configured only `recallModel` (for a fast selector) no longer gets ops (review/correction/flush/drain) silently billed to the slow session model; a typo'd `model` falls THROUGH to `recallModel` instead of straight back. Ref resolution lives in ONE place (`llm.ts` `resolveModelRef`); `selector.ts`'s `resolveRecallModel` delegates (D3 semantics untouched: unresolvable recallModel still means recall OFF).
- Compact flush (`session_before_compact`, 60s, follows event.signal) is unchanged — it rides an already-waited, Esc-abortable path.

### Changed (recall delivery v1.2 — zero screen blocking, spec amendment)

### Fixed (goal, interrupt safety)
- **Escape can always interrupt again while a goal is active**: the goal module's Esc-to-pause raw-input listener ran the FULL pause flow (disk writes, UI updates) synchronously inside the TUI's input-dispatch loop — when the agent was stuck (e.g. a hung audit), that synchronous side-effect chain could break the dispatch before the focused component ever saw Escape, leaving no way to interrupt. The listener now (a) never claims Escape while the agent is busy — busy Escape belongs to the interrupt path and passes through untouched, (b) dispatches the pause on the microtask queue wrapped in try/catch (the raw-input channel is observation-only; nothing in it can disturb the input chain), and (c) pauses only while the agent is idle (the convenience binding survives for idle sessions). Pinned by 5 direct cases (busy pass-through / async idle dispatch / throwing pause contained / non-Escape keys ignored / headless no-subscription).

### Fixed (goal-hijack, spec 2026-10-01-goal-hijack-fix)
