# Changelog

## Unreleased

### Fixed (then_run success badge + zero-wrap discipline — spec 2026-10-05 AR1005-FU)
- **Successful fused runs now actually show the success badge**: the result-status scan looked for a `[then_run:ok]` token that production never writes (it writes `[then_run:succeeded]`), so every successful `then_run` rendered badge-less. Result interpretation moved to one pure module (`action-fusion/outcome.ts`): the structured `details.thenRun` outcome is the first authority — a command log containing the opposite marker can no longer flip a known success — and text compatibility (legacy replays without metadata, thrown failed/skipped error results) is line-anchored (a protocol line or a production text-block start; the legacy `ok` alias stays recognized for history; prose merely containing the token no longer matches). UI label text unchanged (`✓ ok`); the protocol token is NOT renamed.
- **Plain write/edit can no longer be badge-wrapped by their own output**: renderers now consume the host render facts (`ToolRenderContext.args`/`isPartial` — contract AR1005-FU-HOST, compile-pinned): a call whose args carry no `then_run` returns the builtin renderer object untouched even when the result body contains a marker, and partial/streaming results never show a terminal state. Hosts without those fields keep the legacy marker-scan path. `fusedCount` keeps counting only real structured successes; interpretation never rewrites `content`/`details`.

### Fixed (goal audit pre-abort + session release — spec 2026-10-05 AR1005-AU)
- **A pre-aborted `update_goal` no longer starts audit model work**: the completion-audit envelope now establishes its internal-cancellation result first, then connects the tool signal, then checks its current state — a call that is already aborted when the audit starts never invokes the auditor and returns the existing rejected outcome ("aborted by user, goal remains active"), while the started event and the `completion_requested`/`audit_started`/error `audit_result` ledger semantics stay as they were ("started" = the flow was requested, not that the model ran). Timer and both abort listeners are released on every exit path.
- **The auditor session cannot leak on any path**: the moment session creation resolves, the session is covered by a try/finally over its entire remaining lifecycle — cancellation during creation skips the prompt and disposes exactly once; `subscribe`/`prompt`/`unsubscribe` failures (including a throwing unsubscribe) all still dispose, each cleanup step guarded so one failure cannot skip the other; a creation rejection never calls a nonexistent disposer. A late completion after the flow already timed out or aborted can only clean up — it returns an aborted error outcome, never an approval. `sessionAdapter` is the new internal test seam (controlled adapter vs the real `createAgentSession`).

### Fixed (recall request lifecycle — spec 2026-10-05 AR1005-RC)
- **A session being replaced/shut down can no longer crash or ghost-deliver recall**: the recall machine gains a terminal `dispose()`; `session_shutdown` (any reason) disposes it synchronously, `session_start` defensively disposes for reload/resume drivers, and rebuilding/closing recall (model or settings change) disposes the old machine before the new one exists. Every request now owns a generation + AbortController + wait timer + cancelled resolver, so a newer message, abort, dispose or replacement invalidates it immediately — an in-flight `await` returns null right away (never hangs on a selector that ignores the signal) and a LATE completion reads no history, delivers nothing, mutates nothing. The baseline defect — reproduced against the real `ExtensionRunner`: after `invalidate()` a parked selection's completion read the stale ctx inside a void'd promise chain → `unhandledRejection` — is now pinned by contract AR1005-RC-HOST (isolated subprocess; zero sends, zero unhandled).
- **`onUserMessage` is now a total promise**: entry-stage throws (files/history/derive) and deferred-stage throws (history re-read/assemble/deliver) converge to null with at most one controlled diagnostic per failed request — the steer wiring's `void machine.onUserMessage(...)` can no longer produce an unhandled rejection. Deferred delivery commits its run-dedup and delivery counters only AFTER `deliver()` returns successfully (a throwing `sendMessage` on a stale session no longer permanently marks the file as delivered). Normal agent_end still lets an in-flight selection complete and deliver (v1.2 semantics preserved); the wait timer is cleared on every exit path.

### Fixed (JSON extraction string fidelity + lazy candidates — spec 2026-10-05 AR1005-JS)
- **`lib/json-lift.ts` repair no longer rewrites string bodies**: when a model reply had BOTH a genuine trailing comma and a string containing `,}` / `,]`, the old string-blind regex repaired the real comma AND rewrote the string (`"literal ,} sequence"` silently became `"literal } sequence"` — reproduced against the real parser). Repair is now a character-state scan tracking strings and backslash escapes: only an OUTSIDE-string comma followed by whitespace and `}`/`]` is removed, together with that whitespace; everything else passes byte-identical. Affects all four consumers (modes classifier verdicts, memory ops, recall selection, review verdicts).
- **Valid fenced/whole-text JSON no longer pays the span scan**: candidates now come from a private lazy generator shared by `jsonCandidates` (collects) and `liftJson` (iterates); the first accepted candidate ends generation, so the string-aware balanced-span scan — quadratic on pathological inputs (2K/8K/32K `{` measured 5.3/55.9/887.8 ms at baseline) — never runs for inputs whose fence or whole text already parsed. Candidate order and dedup semantics are unchanged. Inputs that still NEED the span fallback keep the disclosed quadratic worst case (deliberate, per spec AR1005-JS-03).

### Fixed (goal audit bounded-wait — spec 2026-10-04-goal-audit-hang-fix)
- **`update_goal` audits can no longer hang forever**: the completion audit now runs under a total budget (default 10 min, `auditTimeoutMs` in `.pi/goal-auditor.json`, floor 60 s). Root cause fixed live on 2026-10-04: the in-process auditor's own `find /Users/gd32 …` wedged in `~/Library/CloudStorage` (File Provider getattrlistbulk), the bash tool has no timeout, and `session.prompt()` took no signal — so the tool result never came back and the whole session froze, un-Esc-able. On expiry (or user abort) the audit now returns a rejected outcome with a `timed out`/`aborted` message, the goal stays active, and the audit is re-runnable; timeout aborts the auditor session via `AgentSession.abort()` (verified against the 1.0.1 run-loop: `prompt()` settles after abort) and the in-memory session is disposed. The auditor prompt and system prompt now forbid home/CloudStorage/network-volume scans and long-running foreground processes, confining inspection to the project directory. Unit regression (hung fake auditor → timed-out rejected outcome, abort propagation) pins the guarantee; bash-tool timeout injection was investigated and dropped (no option point in `BashToolOptions`; total budget covers it).

### Added (goal cost accounting — spec 2026-10-04-goal-cost-accounting)
- **Goal usage now carries USD cost alongside tokens**: `GoalUsage.costUsed` (fractional, upgrade-safe — pre-cost records read as 0) accumulates `usage.cost.total` from parent assistant turns AND from `tool_result` events that report execution usage (subagent runs, codemode `models.classify`/`generateImages`). Fixes the structural undercount verified 2026-10-03: three reviewer subagents (1.94M tokens / $0.49) were invisible to the goal ledger because only `role==assistant` messages were counted. Cost renders in the goal footer, one-line summary, `/goal` panel, compaction summary, pool list, "goal achieved" line, and archive report (2 decimals ≥$1, 3 below — flash-tier rounds read $0.023, not $0.02).

### Changed (pi 1.0.x adaptation — spec 2026-10-03-pi-1.0-adaptation)
- **Host compatibility widened to pi 1.x**: all four `@earendil-works/*` devDependencies move 0.99.1 → 1.0.1, and the three earendil peerDependencies open their ceiling from `<1.0.0` to `<2.0.0` (floors unchanged). Verified additive-only for every symbol core imports (pi-tui export lines extended, pi-ai/pi-agent-core no removals); the contract suite's real-package imports (`pi-host-semantics` ③④⑤⑥) now run against 1.0.1. Recorded as DEVIATIONS #97.
- **codemode interaction pinned** (2 new tests in modes): ask mode passes the `codemode` tool body silently — by design, since a script's nested tool calls go through the full agent tool pipeline (`tool_call` gates apply per tool); plan mode's snapshot/restore keeps `codemode` in the active list while the gate denies it (activity and gating are orthogonal). Plan-mode denial semantics unchanged (META-04).

## 0.2.1 (2026-10-03)

### Changed (architecture review 2026-10-03 — C2/C3/C4)
- **`/compact` no longer waits on a memory-flush LLM call (~10s typical, 60s cap)**: the awaited `session_before_compact` flush had relocated the old shutdown stall to every compaction. Compact now stages the unextracted tail as a queue record through the same zero-LLM seam as shutdown (one shared `stageUnextractedTail` — the two paths can no longer drift); the next same-project `session_start` drains it in the background.
- **`modes/utils.ts` (1247-line nine-concept grab-bag) split into concept modules**: `bash-analysis.ts` (tiered bash adjudication), `path-safety.ts` (outside-cwd/sensitive paths + project identity), `outside-writes.ts` (snapshot engine), `plan.ts` (plan.md file + plan text grammar), `mode-prompt.ts` (anchored injection + skills filter), `auto-risk.ts`, `ui/format.ts`. Pure move — disk paths, behavior, and the contract-pinned `getPlanFilePath` layout unchanged.
- **JSON-lift unified in `lib/json-lift.ts`**: one string-aware implementation replaces four drifted copies (modes classifier, memory ops, recall selector, review verdict). Fixes a real recall-selector bug — a `}` inside a string value broke span extraction and silently counted a parse failure. Trailing-comma/BOM repair now applies to all four consumers; review's brace-lift fallback now also fires when fenced blocks parse but are not verdict-shaped.
- **observation-pack: large tool results are analyzed and stored once per process, not once per provider request** (arch review C1): the projection state now memoizes candidate identity (keyed root/toolName/toolCallId — tool results are immutable in the append-only transcript) and skips the EEXIST full-read + re-hash verification for already-stored objects. Steady-state requests cost one Map.get + a placeholder slice instead of ~3× sha256 + a full disk read per >10KB result; fail-open retry semantics unchanged (a failed store is not memoized).
- **Memory auto-extraction now runs at run end, not mid-run**: the background review (bulk memory extraction) used to fire the moment a turn threshold hit — extracting from a conversation still in flight, and repeatedly on long tool-heavy runs. It now fires once per completed run (`agent_end`), with a bounded 60-part window (a monster run extracts its most recent window; the prefix waits for the next pass) and an empty-window guard (no LLM call when nothing new accumulated). User corrections still capture within 3 turns (their freshness window is what matters).
- **`/memory` no longer mislabels recall as "unresolvable" on a fresh session**: the panel read the last agent-turn's state, so before any turn a configured-and-valid `memory.recallModel` was reported as `recallModel unresolvable`. The panel now re-attempts machine creation before reporting (idempotent, no LLM call); genuinely unresolvable refs still report as such.
- **The memory policy now names the REAL project-memory directory**: the injected `<memory-policy>` block said `PROJECT memory (<project>/memory/)` — a literal directory inside the repo — while the implementation reads/writes `~/.pi/agent/projects/<git-root>/memory/`. A session following the literal text wrote memories into the repo root (untracked, never indexed, never recalled). The policy now interpolates the actual absolute path and explicitly forbids the in-repo `memory/` location (regression-pinned at both the unit and e2e seams).
- **memory: per-message duplicate work eliminated on three paths** (arch review C7): recall reuses the entry-time candidate pool at deferred delivery (the second `files()` directory scan per selection is gone; the two `deriveHistory` passes stay — they are semantically required, RV-07); `conversationParts` walks the branch backward and stops at the window (was: full-branch text extraction to keep the last 6/60 entries); `scanMemoryDirCached` gains a 1s fresh-window (second and later scans in a turn skip the readdir+stat fingerprint pass) with explicit invalidation wired into every internal write path (`atomicWriteFile`/deletes/consolidate/importers). External edits outside pi are now visible within ~1s instead of instantly.
- **goal: paused-goal auditor objection now carries the goalId header** (arch review C6): the two hand-copied `[AUDITOR REJECTION]` prompt injections (an upstream copy-paste drift — same copy, drifted headers, one unreachable extra gate) are unified into one `auditorRejectionBlock` builder; the paused prompt's block now matches the `[AUDITOR REJECTION goalId=…]` marker format used everywhere else in the goal prompt family. The render trio moved to `goal/renderers.ts` (no behavior change).
- **alt+t now belongs to the effort module and can no longer corrupt the effort state on single-level models** (arch review C5): the old hardcoded six-step table lived in modes and probed by WRITING each candidate level (`setExplicit`) until one stuck — on a model supporting only one level it pinned a clamped value into the persistent explicit slot, flipping the source to "session" and suppressing per-mode profile effort for the whole session. alt+t (and ctrl+shift+e, which had the same flaw) now share one model-aware cycle with a zero-write guard: single-level models get a notice instead of a corrupting write, and the cycle follows the model's actual supported levels. The stateful model-profile half of modes moved to `profile-apply.ts` (pure internal move).
- **session_recall works on real machines again, and is now bounded** (arch review C8): the sessions-dir path used the projects-layer naming (`-Users-…`) while pi writes the sessions layer with wrapping dashes (`--Users-…-`) — the tool silently returned "no sessions found" for every real project (found by adversarial plan review R2 against the live machine). Now fixed; additionally the scan is async (no more event-loop blocking on large session dirs), bounded by three caps (200 files / 1MB per file as a PARTIAL read, never a whole-file skip / 8MB total budget), and appends a transparency footer (`scanned=… truncated_size=… budget=… bytes=…/…`).

### Fixed (memory automation survived in-process session switches — spec 2026-10-03 A1)
- **A dead AbortController no longer silently kills all memory automation after `/new` `/resume` `/fork`**: the host fires `session_shutdown` (whose cleanup aborts the shared controller) and then REUSES the same handler closures for the next session in the same process — the review gate `!signal.aborted` stayed false forever, the cursor froze, counters never reset. `setupAutomation` now resets every per-session closure state and re-arms the controller on `session_start`. Pre-existing bug found by adversarial review; the queue design depends on the fix.

### Changed (memory exit path zero-LLM — spec 2026-10-03-memory-exit-flush)
- **`session_shutdown` no longer runs an LLM flush**: the host awaits every shutdown handler serially with no timeout, and the old awaited 10s flush on the session model measurably stalled EVERY long-session exit for the full budget (CPA→glm-5.3 on a real 23KB tail window: 11–12.4s cold, 10.5s even with a cache hit — generation speed, not prefill, was the bottleneck). The handler now stages the unextracted tail (cursor-relative suffix, ≤60 parts × 2000 chars) as ONE atomic JSON record under `~/.pi/agent/memory-queue/`; the NEXT same-project `session_start` drains it in the background (≤5 records per drain, ≤3 attempts per record with pre-call attempt persistence, exact `projectsDir` routing, 7-day age cap, 2MB dir GC, apply-fatal = consume). Records are a plaintext second copy of the session tail — disclosed in `/memory` docs. Contract-registered under P0-CT-09.
- **Side-channel model fallback chain is now `memory.model → memory.recallModel → session model`** (was `memory.model → session model`): a user who configured only `recallModel` (for a fast selector) no longer gets ops (review/correction/flush/drain) silently billed to the slow session model; a typo'd `model` falls THROUGH to `recallModel` instead of straight back. Ref resolution lives in ONE place (`llm.ts` `resolveModelRef`); `selector.ts`'s `resolveRecallModel` delegates (D3 semantics untouched: unresolvable recallModel still means recall OFF).
- Compact flush (`session_before_compact`, 60s, follows event.signal) is unchanged — it rides an already-waited, Esc-abortable path.

### Changed (recall delivery v1.2 — zero screen blocking, spec amendment)
- **`recallWaitMs` default 4000 → 0**: the prompt path never blocks the screen on the selector. A parked selection **delivers the moment it completes** via `sendMessage(triggerTurn:false)` — pi queues it as a pending custom message and flushes at the next turn_end (the first assistant message's end at the earliest): request #2 sees it within the run, the next turn's request #1 otherwise. The turn_end-gated deferred path and its discard-at-run-end semantics are gone (`onTurnEnd` removed; `agent_end` no longer aborts in-flight selections — latest-wins supersede happens at the next user message). `display:false` keeps the block invisible in both TUIs (vanilla filters live+resume; cctui doesn't touch the custom-message path).

### Changed (memory recall v2 — BEHAVIOR CHANGE, spec 2026-10-02-memory-recall-v2 R1)
- **Recall now requires explicit configuration**: with no `memory.recallModel` in `~/.pi/agent/settings.json` there is NO automatic recall at all (previously lexical recall ran by default). Configured: recall = at most once per real user message, persisted into the transcript as a `pi-memory-recall` custom message — the request-level context projection (which re-injected one frozen selection on every request: ~30× cache-miss bytes, the "same five memories every turn" failure) is gone. Session-scoped hard dedup (one file surfaces at most once per compaction window), history-derived read suppression and byte budget, per-file truncation with a read-the-full-file path note instead of silent >4KB skips.

Contract pins: `pi-memory-recall` customType + details v1 field set (P0-CT-08) and real-package `buildSessionProjection` custom-message `details` survival (pi-host-semantics ⑥).

### Fixed (goal, interrupt safety)
- **Escape can always interrupt again while a goal is active**: the goal module's Esc-to-pause raw-input listener ran the FULL pause flow (disk writes, UI updates) synchronously inside the TUI's input-dispatch loop — when the agent was stuck (e.g. a hung audit), that synchronous side-effect chain could break the dispatch before the focused component ever saw Escape, leaving no way to interrupt. The listener now (a) never claims Escape while the agent is busy — busy Escape belongs to the interrupt path and passes through untouched, (b) dispatches the pause on the microtask queue wrapped in try/catch (the raw-input channel is observation-only; nothing in it can disturb the input chain), and (c) pauses only while the agent is idle (the convenience binding survives for idle sessions). Pinned by 5 direct cases (busy pass-through / async idle dispatch / throwing pause contained / non-Escape keys ignored / headless no-subscription).

### Fixed (plan-gate MCP shape leak, arch batch B1)
- **plan mode now recognizes every MCP call shape**: the read-only plan gate used a private double-underscore-only regex that had drifted from the rule-family authority — single-underscore native names (`mcp_exa_search`), proxy-shaped calls (tool `mcp` with `input.tool`), direct-named tools on `PI_CORE_MCP_DIRECT_SERVERS`, and bare `mcp_*` names all slipped past it (every MCP tool is a potential mutation, so plan denies them outright). The pure shape core now lives in `lib/mcp-shape.ts` and is shared verbatim by the authority (`canonicalizeMcpTool`) and the plan gate, so the two consumers cannot drift again (4 new shape pins + the p4-families authority pins stay green).

### Fixed (goal-hijack, spec 2026-10-01-goal-hijack-fix)
- **Subagent spawns no longer fail while a goal is active**: the goal module used to adopt the project's on-disk active goal in subagent child sessions (same cwd) and arm its continuation — the `<pi_goal_continuation>` checkpoint occupied the child's agent loop before the dispatched task prompt could be delivered, so every subagent dispatch in the project failed with "Agent is already processing a prompt". Child sessions (`PI_SUBAGENT_CHILD=1`) now skip disk-goal adoption entirely and never arm continuations (belt and braces); parent-session behavior is unchanged (red-green pinned).
- Test harness: `FakeHost.makeCtx` gained `idle` / `hasPendingMessages` options (the missing `hasPendingMessages` made the goal continuation path silently no-op in fakes — pre-existing fidelity gap).


### Fixed (memory recall, spec 2026-10-01-memory-recall-fix v3.1)
- **Per-turn pin & re-project**: memory recall now selects once per user turn and re-projects the byte-identical block for every provider request in the turn — previously it re-selected per request (selection drifted on tool output) and re-billed the session budget every request until recall went permanently silent at the 60KB cap.
- **Two-domain matching**: a memory qualifies via title+description overlap (≥2 tokens) or the tiered fallback (≥1 primary + ≥2 body hits); body-only overlap no longer turns every large file into a universal match (the "npm-publishing recalled during goal-dialog work" noise class).
- **Billing-only dedup**: each file is charged to the session budget once per session; surfaced files stay re-projectable across turns. Read files remain excluded until compaction.
- **Cache discipline (MR-09)**: injections are tail-appended only (never mid-history, never in the system prompt) and byte-stable within a turn; the system-prompt memory index is byte-stable while the memory dir is unchanged.
- Test hermeticity: `mode-inherit` "ignores invalid modes" now clears ambient `PERMISSION_MODES_INHERITED_MODE` (pre-existing leak when running the suite inside a pi session).


### Fixed (goal dialog height management, SPEC 2026-10-01)
- **goal**: the questionnaire / draft-confirmation dialog now manages its own height instead of overflowing the terminal — pinned header (separator, tab bar, question), scrollable context body (`ctrl+u`/`ctrl+d` half page, `PageUp`/`PageDown` full page, offset clamped), pinned footer with a ≤7-row option window and `(+N more)` hint. Works in both fullscreen and non-fullscreen tui modes, so options are always visible on long goal drafts. The selected option row gets a `selectedBg` highlight (❯ marker); short dialogs render byte-identical to before apart from that highlight. Layout math lives in `extensions/goal/questionnaire-layout.ts` (pure, table-tested).
